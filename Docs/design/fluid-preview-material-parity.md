# Fluid の見た目、材質、編集視点

## 目的と一致の基準

Fluid Editor の 2D と 3D は同じ `.fluid`、再生時刻、色ランプ、密度から色への変換、透過と背景合成を使う。2D は平面、3D は体積を解くため、輪郭と粒子配置の画素一致は要求しない。どちらを焼くかは `[bake] mode` が決め、編集ビューが異なる場合は明示する。プレビュー品質を下げても時間刻み、色、透過の意味を変えない。

## アセットの責務

- `.fluid` は発生源、力、ソルバー、ベイク条件の正本。Fluid ライブラリは Math 以外に依存しない。
- 同名の `.mat` はシーンと VFX が参照する描画資産。2D と 3D のベイクは共通の `FluidAssetWriters` を通して `.mat` を更新する。`.mat` は `RenderPath::Particle` と焼いたテクスチャの `guid:` 参照を持つ。PNG と DDS の両方がある場合は、Git で保持される PNG を優先する。
- ベイクが管理するキーは atlas、flipbook、合成、motion vector、6-way の設定に限る。その他の手編集値は再ベイク後も残す。既存 `.mat` が読めなければ上書きせず失敗理由を出す。
- VFX やシーンへの配置は `.mat` を参照する。3D レシピもベイクした flipbook `.mat` を通す。編集中のライブプレビューだけは未保存レシピを直接描いてよい。これは配置用アセットではない。
- 既存の `.fluid` と `.mat` の読み込み互換を維持する。3D の直接体積描画案は別の設計課題とし、この設計に混ぜない。
- 通常の Bake は `.mat` まで完成して成功とする。材質または指定した VFX の書き出し失敗はジョブの失敗として報告する。旧 AI API の `updateMaterial` 入力は読み取り互換のため受け付けるが、Bake では値を無視して `.mat` を更新する。プレビューのジョブは書き出さない。

## 2D / 3D の選び方

- Viewport の 2D / 3D は編集中の観察視点で、`[bake] mode` はシミュレーションと書き出し経路を決める。Viewport を回しても保存済みのベイク視点は変わらない。
- 正面向きの炎、オーラ、魔法、短い煙など、輪郭・彩度・発光の演出を優先する板の VFX は 2D ベイクを先に試す。JetFlame もこの用途なら 2D が実用上の第一候補になる。
- 奥行き方向の流れ、体積内の吸収と散乱、方向別照明を焼き込みたい場合は 3D ベイクを選ぶ。ただし現在の出力は固定視点から撮った flipbook billboard であり、シーンのカメラを回しても視差は得られない。真に視点依存の体積表現には別の描画方式が要る。
- 2D と 3D はソルバーの次元と温度分布が異なるため、同じ `.fluid` でも形・粒子配置の画素一致は保証しない。色と合成の計算契約を揃え、編集画面ではモードと固定視点の制約を明示する。

## Fluid Editor の 2D / 3D

- ループの混合率は `FluidLoopKeepWeight` を 2D / 3D で共有する。0 コマ目は最終コマの続きだけを使い、混合区間の終端まで smoothstep で元の先頭へ戻す。両端で混合率の傾きを 0 にし、切替時に残った画像が急に消えるのを抑える。既存アトラスへの反映には再ベイクが必要。

- 同じ `FluidRenderSettings` から光学密度、色ランプ、発光、ディテールを評価する。片方だけにある定数や暗黙の倍率をなくす。透過は事前乗算色として背景へ合成する。
- ディテールは 2D / 3D とも 4 オクターブの値ノイズ、同じ層オフセット、振幅正規化、二層ブレンド、密度と温度への同一倍率を使う。2D の座標はソルバーが移流し、3D は速度場から近似して移流する。3D 固有の輪郭の domain warp は体積格子の補間を補う描画処理として残す。Distortion の覆いには両モードともディテールを掛けない。
- 歪みの速度符号化は `FluidRenderMath.hpp` を 2D / 3D の C++ 出力で共有する。HLSL のプレビューは同じ頭打ちと画像 V 軸の反転を使う。
- Fire の発光は温度・燃料に由来し、煙の密度と独立に積分する。初期密度が 0 の炎でも、温度がある区間をレイマーチから除外しない。煙の吸収は光路上の発光に作用するが、発光強度そのものを煙の不透明度で乗算しない。
- Fire の発光係数は `[bake] extinction` を基準にし、`[render] opacity` で変わる煙の消散係数から分離する。6-way 材質を事前乗算で保存するときは、Positive の alpha を煙の照明だけへ掛け、Negative の発光マスクはその alpha と独立に合成する。既存の通常アルファ 6-way 材質の計算は維持する。
- 3D の温度場は最大発生源の温度で正規化して格納するが、燃焼後には 1 を超えうる。Fire の発光評価では上限 1 に切らず、`T⁴` と色温度へ同じ値を渡す。Emission Ramp を使う Fire は 2D と同じく Ramp 自身で明るさを決め、追加の `T²` を掛けない。JetFlame の `blackbody_max_kelvin=2400` は `render.fire_kelvin × max(source.temperature)` (`1500 × 1.6`) に合わせ、正規化前の 2D 温度と同じ色温度になるようにする。`emission_intensity=36` は 3D の明るさ校正値として維持し、2D の `fire_intensity=1` とは分ける。
- 6-way Fire は Negative の発光マスクを放射量へ掛けてから `1 - exp(-radiance)` のソフトニーを適用する。薄い炎で順序を逆にすると、プレビューより Scene が大幅に暗くなる。
- 新しい 6-way Bake は Positive / Negative の方向別照明に加え、被覆率で重み付けした煙の色 `_6wayC` と、プレビューと同じレイマーチで積分した発光色 `_6wayE` を保存する。Scene は前者で方向別照明へ局所色を戻し、後者を発光マスクで再乗算せずに合成する。古い `.mat` が両方の色アトラスを持たない場合は従来の Negative マスクと単一発光色を使う。
- プレビューと色 Atlas のベイクは同じ発光積分を使い、露出と表示色空間への変換は出力先で一度だけ行う。8 bit Atlas のクリップは明示し、薄い炎の RGB が alpha を超える事前乗算表現を維持する。
- プレビューの背景合成は 2D / 3D ともリニア色で行い、最後に共通の gamma 2.2 近似で表示色へ戻す。チェッカーはビューポート上で同じ大きさにする。Fire の `render.fire_intensity` と `render.use_emission_ramp` は両経路へ反映し、3D 専用の `bake.emission_intensity` は既存資産の校正値として保持する。
- Scene の Game view はカメラ露出、トーンマップ、照明を通る。これらの設定に依存する最終画素値は Editor プレビューと一律には一致しない。
- 3D ソルバーとレイマーチの内部 Bake シェーダーは、ゲームプロジェクトに複製が無い場合もエンジンのアセットルートから解決する。プロジェクトの欠落パスを絶対化した後ではエンジン側へ戻れないため、内部の論理パスから探索する。
- `--batch --hidden` の DX12 検証は、遮蔽されたウィンドウでも画面外 RT のフレームを記録する。通常のエディターは遮蔽中の描画休止を続ける。プレビューのジョブ完了だけでなく、画像の非黒画素と色も確認する。
- 3D の光学密度は既存の `bake.extinction` を基準にし、`render.opacity` の既定値に対する倍率を掛ける。既存レシピの既定値では従来の 3D 出力を維持する。3D の専用照明と体積積分による差は残る。
- 3D ビューは体積の境界、中心、床グリッドと軸を薄く重ね、透過部でも奥行きと向きが分かるようにする。ガイドはプレビュー画像やベイク出力へ焼き込まない。
- 3D の視点操作は SceneEditor と同じ方位ボールを右上に置く。ドラッグで yaw / pitch、軸を押すと正面・側面・上下へスナップし、短時間で補間する。視点操作はソルバーを開き直さず、保持している体積を再レイマーチする。画面上の部品ギズモは同じカメラ行列で投影し、操作中は方位ボールと競合させない。
- ベイクのカメラ yaw と編集用 orbit を分ける。Fit は pan / zoom のみ、Reset View は orbit もベイク視点へ戻す。ビューを回しても保存済みベイク設定は変えない。
- 2D でのハンドル操作と 3D の ImGuizmo は Undo をドラッグ単位で積む。非対応の回転・拡縮は無効理由を表示する。

## MaterialPreview の Normal

- 現状の `Normal` チャンネルは Surface / Skinned のみ。これは照明に使う合成後の法線を表示する機能として残す。
- `.mat` の `normal` テクスチャを持つ材質では、Flavor に関係なく Normal map の RGB を確認できるプレビューを追加する。材質と同じ GUID 解決・テクスチャ読込を使い、欠落や読込失敗は理由を表示する。Normal map が無い材質には不要な枠を出さない。
- Shaded ビューでの法線効果は既存シェーダーを使う。生の Normal map と合成後の法線を混同しないラベルにする。

## 確認

- 同じ `.fluid` を 2D / 3D に切り替え、色・透過・時刻・背景の対応を確認する。3D の視点を回してもソルバーの世代とベイク設定が変わらないことを確認する。
- 2D / 3D を焼き、同名 `.mat` の `RenderPath`、テクスチャ GUID、flipbook と 6-way / motion の切替を確認する。手編集した非管理キーを保持し、読めない `.mat` は保護する。
- `JetFlame.fluid` の 3D プレビューと再ベイク後の Scene 表示で、温度が高く煙が薄い炎の芯にも発光が残ることを確認する。6-way を使う場合は Positive/Negative の実在するファイルと `.mat` の参照・発光マスクが一致することを確認する。
- JetFlame の旧 `.mat` は Git 管理外の DDS を参照していた。再ベイク後の `.mat` はレシピの `six_way_lightmaps` に従い、Git で保持する Positive/Negative/色/発光 PNG と Motion Vector PNG を GUID で参照する。
- Normal map を持つ Surface と Particle、持たない材質で MaterialPreview を確認する。Surface の合成後 Normal チャンネルも残す。
- C++ 変更は `Tools/AgentBuild.ps1 check`、必要な既存テストは同スクリプト経由で実行する。実機の表示確認は Fluid の 2D / 3D と MaterialPreview をエディターで確認する。
