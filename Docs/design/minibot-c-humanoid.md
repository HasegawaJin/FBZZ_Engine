# MiniBot C — 人型リグと一刀モデルの制作仕様

- Status: 完成モデル・22モーションを制作し、出力対象を整理済み。現在の正本は MiniBotC_PlayerMotions.blend。リグ制作開始時のFBX往復検証と、完成版のFBZZ検証は区別する。完成版のFBX出力・FBZZ再生検証は未実施。
- Author: Hasegawa Jin
- Date: 2026-09-13
- 上位方針: [Blender DCC パイプライン](blender-dcc-pipeline.md)

## 採用する方向

- 造形は Tripo で生成し、Blender で修正・材質・リグ・モーションを仕上げる。入力素材と使用方法は `Docs/Art/MiniBotC/TripoInput/README.md` (追跡外)。Blender での手続き的な造形は試作段階で中断し、完成モデルとは扱わない。
- ユーザーが選択した C 案。白い装甲、黒い関節、緑の目とコア、頭部の左右フィン、長めの脚を維持する。
- 武器は緑の発光刃を持つ剣 1 本。片手操作と両手で支える動作の両方に対応する。
- 既存モーションは引き継がない。旧骨格の命名、可動制限、ポーズとの互換を新設計の条件にしない。
- 人型の標準的な骨格と操作系を使い、歩行・走行・剣技・登攀を制作しやすくする。

## 制作可能性と品質の判定

BlenderMCP から Blender Python を実行できるため、メッシュ、モディファイア、材質、骨格、
ウェイト、制約、アクションの制作は可能。C 案の分割装甲と人型の構成も実装可能な範囲にある。

ただし、接続確認はモデル品質の実証ではない。生成画像を一度の処理で完成モデルに変換するとは扱わない。
頭部・胸部の面構成、指の形、三方向の形状整合、装甲の干渉、足の接地は、実モデルを複数視点と動作で確認する。
画像の三面図は見た目の参考であり、投影や寸法の完全な整合を保証する設計図ではない。

## 人型骨格と操作系

Blender 内で制作する操作用リグには Rigify の人型メタリグを用いる。指を備え、不要な顔の骨格は省く。
ゲームへ出す骨格は別に定義し、制約の評価結果を通常のボーン変換へベイクする。

| 部位 | 出力骨格の構成 |
|---|---|
| 全体・胴体 | `Root → Hips → Spine → Chest → UpperChest → Neck → Head` |
| 左右の腕 | `UpperChest → Left/RightShoulder → Left/RightArm → Left/RightForeArm → Left/RightHand` |
| 左右の脚 | `Hips → Left/RightUpLeg → Left/RightLeg → Left/RightFoot → Left/RightToeBase` |
| 指 | 左右それぞれ親指・人差し指・中指・薬指・小指を 3 節。手首以下へ接続 |
| 追加要素 | 必要最小限の捻り補助骨、武器ソケット。人型の必須鎖とは分ける |

基本構成は 53 ボーン。補助骨とソケットを含めて 64 前後を目標とし、出力後の実数を検査する。
表の `Left/Right` は左右それぞれの名前を表す表記で、実ボーン名にスラッシュを使わない。
既存の命名認識へ合わせるだけでなく、FBX 再読み込み時に階層とトラック対応を検証する。

- 手足に IK/FK の切り替え、肘・膝の向きを指定する制御、足裏の接地とつま先回転を設ける。
- 左手を剣の補助グリップへ追従させる制御を設け、片手から両手への切り替えを可能にする。
- 武器の所有は右手側の 1 系統にまとめる。剣と左右の手が互いを追従する循環制約を作らない。
- 目の表情は別の表現手段で扱い、口・頬など不要な顔骨を増やさない。
- 標準の人型構造は既製の操作系やモーションの利用を助けるが、骨名だけでは体格差の補正は完了しない。

## 動かすための形状調整

- 腕を胴から離した左右対称の A ポーズを制作基準とする。必要な T ポーズを別に用意できる構成にする。
- 肘と膝は曲がる向きが明確になる程度に軽く曲げ、関節軸とボーンロールを左右で揃える。
- 首に頭を傾ける空間、鎖骨に腕を前へ出す可動を確保する。肩装甲は腕の挙上と交差を妨げない。
- 胸と骨盤を別々に回せる腰を設け、前屈・捻りを 1 箇所のヒンジへ集中させない。
- 股関節の前側、膝裏、肘内側を装甲で塞がない。足首とつま先を分けて踏み返しを可能にする。
- 装甲は原則として対応骨へ剛体的に追従させ、関節の内装など曲がる部分だけを滑らかにスキニングする。
- 指と柄の寸法を同時に設計する。両手で握れる柄の長さを確保する。

## 剣の暫定寸法

現三面図に対し、刀身を 15〜20% 長くする案を第一候補とする。数値は見た目と動作確認で確定する。
厚みや幅まで一律に拡大せず、C 案の軽快さを維持する。発光色は本体と同系統の緑。

刀身を延ばしたぶん、腕を下ろした姿勢の剣の角度と柄の位置を調整する。
直立時に床へ刺さらないだけでなく、屈み、走り、着地、両手持ちで切先が破綻しないことを確認する。

## FBZZ への受け渡し

FBZZ には人型ボーンの分類、足の接地 IK、レイヤー上の名前対応・回転補正・移動倍率による
リターゲット処理がある。確認したこれらの機能を、体格の異なる骨格へ完全自動で適応する仕組みとは扱わない。
新骨格用に Blender で完成・ベイクしたモーションを FBX へ出すことを基本とする。

- 30 fps、1 アクション = 1 FBX = 1 テイクを基本にする。
- Rigify の操作骨・機構骨を丸ごとエクスポートせず、定義した出力骨格と必要な補助ノードだけを渡す。
- 制約、IK、ドライバーは Blender 内で評価し、FBX には再生可能な変換キーを出力する。
- ルート移動と腰の上下運動を分離し、既存の `Root_Motion` 交換規約と整合させる。
- 旧 MiniBot 固定のアクション名・武器 2 本を前提とするエクスポーターは、そのまま新リグへ流用しない。

## 制作順と最初の合格条件

1. 人型骨格と簡易メッシュで C 案の体格を決める。
2. 長めの剣で、腕の挙上、両手での構え、屈み、歩行・走行、着地を確認する。
3. 上記の可動を維持しながら、頭・胴・手足の装甲を仕上げる。
4. 新規の待機・走り・一撃・弾きで品質を確定し、その後に必要なモーションを増やす。
5. FBX を再読み込みし、足の接地、武器と手の位置、スケール、骨数を検証する。
6. FBZZ 上で同じクリップと武器ソケットを確認する。旧資産の参照整理は移行対象を洗ってから行う。
