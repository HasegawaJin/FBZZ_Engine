# Ragdollの部位操作・バランス観測・つかみ

2026-11-03。汎用APIを先に充実させるユーザー選択に基づく。アニメーション優先モードを維持する。
歩行周期、入力割当、足運び、つかむ物の選択、転倒・起き上がり遷移はC#が所有する。

## 部位操作

骨名は物理定義の完全名。GetBodyName / GetBodyStateで物理部位を列挙・観測する。
SetBodyTargetはWorld / Parent空間の重心姿勢・速度と位置/回転の独立した混合率を受ける。
手動目標の空間をその部位の有効制御空間とし、元のSetBodyDrive設定は保持する。
Parentは最も近い物理親の剛体空間で、物理親が無い根ではWorldとして扱う。
standingGuardは手動目標にも最終姿勢の制限を掛ける。物理主体の制御では明示的に無効化する。
ClearBodyTargetでアニメーション目標へ戻す。出力・周波数・全体Active/Passiveは引き続きSetBodyDrive/SetMuscleが所有する。
力はN・トルクはN·mと継続秒数、力積はN·s / N·m·s。剛体へ直接加え、Transformは書き換えない。
継続力は各substepの予測姿勢へ半陰的な速度・姿勢増分を加え、接触生成前に反映する。

### 駆動プロファイル

`ApplyDriveProfile` は物理骨名と項目ごとの差分を一括指定する。保存済みの通常駆動を土台にし、
選択中のプロファイル全体を置き換える。未指定の骨・項目は通常値を継承し、明示した `0`・`false` を反映する。
呼び出し側は用途別の共通値に必要なモデル別設定を重ね、骨ごとにまとめて渡す。
`SetBodyDrive` の個別上書きが最優先で、`ClearBodyDrive` はその時点のプロファイル値へ戻す。
重複骨・不在の骨・不正値を含む一括適用では、既存の設定と補間を保持する。

遷移時間は固定物理時間の秒数を指定する。0 は即時、正の値は現在のプロファイル値から補間し、
再適用時は補間済みの値を次の開始値にする。空の一覧を適用すると通常駆動へ戻る。
座標系は新しい目標サンプルから切り替え、手動目標に空間指定があればそれを優先する。
骨格の再構築時は新しい通常駆動にプロファイルの目標値を解決してから個別上書きを戻す。

### 駆動プロファイルのアセット設計

`.ragdoll` はモデルの剛体、関節制限、通常駆動を定義する。衝突時などの用途別の差分は、ゲーム側の
`RagdollDriveProfileAsset : DataAsset` で保存する。キャラクターの Prefab または Scene の設定が、
使うアセットと部位の対応を保持する。エンジンは物理骨名に解決済みの `RagdollBodyDriveEntry` を受け取る。
適用のタイミング、遷移秒数、衝突の判定、踏み出し、Idle への復帰はゲームの状態制御が決める。

#### 保存と合成

- アセットは `schemaVersion` と部位ごとの差分行を持つ。Prefab 側の参照は `DataAssetRef<RagdollDriveProfileAsset>`
  の GUID を使う。保存キーは固定し、互換性を保てる改名には `FieldKey` と `PreviousFieldKey` を使う。
  新規はバージョン 1 を保存する。保存形式の意味を変える場合は旧版からの明示的な移行を用意し、未知の版は拒否する。
- 差分行の部位キーはゲーム内で安定した ID とする。例えば `chest` を Mixamo の `mixamorig:Spine2` へ、
  `neck` と `head` を対応する物理骨の完全名へ割り当てる。ID の比較は大文字小文字を区別する。
  表示名や骨の列挙順を変えても、保存した ID の意味は変わらない。モデルを差し替えるときは部位と物理骨の対応を設定する。
- 駆動項目は Inspector で保存できる `Serializable` な設定値とし、各項目に `Inherit`、`Set`、`RigDefault` を持たせる。
  `Inherit` は下層を維持し、`Set` は `0` や `false` も適用し、`RigDefault` はその項目の下層差分を取り消して
  `.ragdoll` の通常値に戻す。C# の `RagdollBodyDrivePatch` には、合成後に残った `Set` だけを詰める。
- 用途ごとに、適用するアセットを低優先から高優先の順に並べる。合成の順序は通常駆動、共通差分、モデル別差分、
  実行時の `SetBodyDrive` とする。複数の差分が同じ部位に触れても指定項目だけを上書きする。
  アセットは差分行のみを持ち、アセット参照の順序は Prefab や Scene で確認できる。
- 数値は SDK と同じ単位を使う。周波数は Hz、減衰比と目標速度倍率は無次元、力上限は N、トルク上限は N·m。
  駆動空間は `Parent` または `World`。`Set` の不正値や未知の列挙値は診断を返し、勝手に補正しない。

保存形式と編集は [C# 設定の保存契約](csharp-authoring.md) と
[設定トランザクション](csharp-settings-transactions.md#dataasset-と複数選択) に従う。

#### 検証と適用

1. Play 開始時、モデル差し替え時、明示的な再読み込み時に参照を読み、差分を合成する。省略するレイヤーは一覧から外す。
   一覧内の空参照、GUID の欠損・型違い・破損はエラーにする。各アセットの重複部位、空のキー、不正値を先に検査する。
2. Rig 構築後に、合成結果に `Set` が残った部位を実在する物理骨に解決する。同じ部位への複数の割り当てと、適用一覧で
   複数の部位が同じ物理骨に解決される構成を拒否する。API には上限の 128 骨以内で、一骨につき一行を渡す。
3. 全件が有効になってから `FixedUpdate` で `ApplyDriveProfile` を一度だけ呼ぶ。失敗時は既存 Rig で有効だった設定を保持する。
   初回の失敗や、互換性のない Rig に交換した直後は通常駆動を使う。診断に用途、アセット GUID、部位と物理骨、失敗項目を出す。
   EngineTestScene の検証では適用成功を必須にする。関数が `false` を返した場合と入力例外をどちらも失敗として扱う。
4. 実行中は解決済みの値を個体ごとに保持し、設定の切り替え時に使う。毎フレームのアセット読取や骨名解決は行わない。
   Edit の保存は次回 Play または明示的な再読み込みで取り込む。進行中の衝突試験では一連の動作が終わった境界で候補を反映する。
   同じ Rig 内の遷移は API の固定時間補間に従う。モデルや骨格を交換した場合は新しい Rig に対して再検証する。
5. Rig ごとのプロファイル切り替えは一つの制御元が担当する。通常駆動への切り替えは空の一覧を適用し、一時上書きは
   設定した制御元がそれぞれの終了時に解除する。衝突試験の途中で Idle に戻るときは、現在の用途のプロファイルを使い続ける。

#### 受入条件

- 実装前に合成と適用の期待値をテストで定義する。保存・再読込後の未指定、`0`、`false`、`RigDefault`、
  共通値とモデル別値の優先順、旧版の移行または拒否、欠損参照や骨名違いの全件拒否を確認する。
- 異なる骨名を持つ二つの Rig で同じ共通アセットを使い、対応表だけの変更で正しい部位に適用できることを検証する。
  同時に生成した二体へ別々の差分を適用し、一方の切り替えや一時上書き解除がもう一方に波及しないことを確認する。
- Editor の保存・Undo/Redo、Play と Stop、配布したゲームでの GUID ロードを確認する。
  アセット化の前後で男女それぞれのランダム衝突と十字衝突を同じシードで比較する。Q は既存の連続 12 発を使い、接触順、首と手首の揺れ、
  支持足のずれ、食い込み、強い衝突の二歩、中央 Idle 復帰を表明し、横からの描画も比較する。

## バランス

EngineTestScene の Active Ragdoll 歩行は WASD の前後左右と斜め入力を使う。
入力はモデルの前方・右方を基準に正規化し、逆向きの同時入力は相殺する。
支持足を接地位置に保持し、遊脚の着地後に次の進行方向の足を運ぶ。
腰は両足の中間へ位置・速度・加速度を連続につなぎ、横方向の足運びでは左右の間隔を確保する。

重心・質量加重速度・支持点・支持法線・支持面速度・接触凸包に対する余裕を観測する。
自己接触とつかみ拘束を接地支持に数えず、法線が重力の逆方向を向く接触だけを使う。
Contact.Valid は min(contactMargin, 0.001 m) の数値許容内の接触を含む。Penetration=0 は貫通がないことを示し、支持なしとは限らない。離れた予測接点は支持・接触数・休止へ含めない。
重力方向に直交する面へ接触点を投影し凸包を作る。点・線の支持もpadding付きで扱う。
CapturePointはCOMの支持面への投影に水平相対速度×sqrt(COM高さ/重力加速度)を加えた近似。
[Pratt et al., 2006](https://www.cs.cmu.edu/~cga/legs/Pratt_Goswami_Humanoids2006.pdf)の線形倒立振子を参考にする。
可変高さ・大きな全身角運動量・滑りを含む転倒保証ではない。無支持・無重力・高さ不足ではCaptureValid=false。
純managedのバランス補助計算は有限の水平加速度を返す。外力や姿勢目標へ使うかはC#が選ぶ。

## つかみ

部位ごとに独立した点拘束。静的なワールド点とWorldが管理するRigidBodyを対象とする。
[UE Physics Handle](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UPhysicsHandleComponent)を参考に、位置のみ/回転保持を選べる。
初回に掴み点を両剛体のローカル座標へ保存する。最大到達距離を超えた要求は既存の掴みを変更しない。
陰的ばね減衰を有限出力で位置パスへ反映し、速度導出後に相手へ逆の力積を返す。
World側を再積分・位置射影しない。静止時の速度に重力×substepの見かけの上向き成分を残さない。
回転保持も有限トルク。MaxForceは正、MaxTorqueの0は回転保持を停止する。
BreakForceは上限適用前の要求力を判定し、切断しなければMaxForceで制限する。
破断力0・破断距離0はその破断条件を無効にする。
Release / ForceLimit / DistanceLimit / TargetLostの理由を取得でき、破断を自動再接続しない。
対象の寿命証明を毎回照合し、破棄・コピー/移動・再利用されたアドレスへ反作用を返さない。
把持中の外部剛体と把持元Rigは同じ衝突グループとして相互接触を除外する。
World側を固定姿勢として解く接触反作用と把持が競合すると、小質量物体へ過大な反作用が蓄積するため。
他の物体・床との接触は継続する。静的剛体の支持面は除外しない。
最後の解除・破断・対象差替後、全形状がRigから2cm以上離れてから相互接触を復帰する。
重なった状態で即時に戻すと、貫通解消の反作用で放した物体が飛ぶため。寿命切れの除外記録は破棄する。
Passiveでも掴みは継続する。End / disabled / 非active階層 / Rig再構築で解除する。
Rig再構築では手動目標と継続力も破棄する。Play複製でランタイム操作を引き継がない。
ゲームの範囲・レイキャスト・把持面の選択はこのAPIの呼出元が行う。

## 実操作で見つかった接触の修正と計測

EngineTestControlledMotionMale / Femaleは、両手の目標追従、胴への力積、
片手解除、0.25kgの箱の運搬・落下、足の接地とバランス補助を段階ごとに撮影・計測する。
保持状態のboolだけでなく、位置誤差・物体速度・解除後の落下も表明する。

動的な把持対象とRigの接触反作用が競合し、長い運搬で物体が約85m移動する不具合を再現した。
相互接触を把持中に除外するだけでは、解除直後にも約72〜78m/sで跳ねた。
除外は最後の解除・対象差替後も重なりが解消するまで保持し、静的な支持面は除外しない。
複数部位の保持、静的支持、失敗した差替、重なった解除、分離後の接触復帰を含むnative157件が成功した。

検証用SDKと通常SDK 0.10.0の両方で、男女の実操作各31項目と従来の操作APIシナリオが成功した。
実測は次のとおり。箱のColliderは常時有効で、床・他物体との接触も継続する。

| 項目 | 男性 | 女性 |
|---|---:|---:|
| 目標保持時の左手/右手誤差 | 0.96 / 1.57cm | 0.37 / 1.66cm |
| 衝撃中の把持点の最大ずれ | 5.17cm | 0.92cm |
| 箱の運搬距離 | 28.65cm | 27.96cm |
| 箱の把持点の最大ずれ | 1.73cm | 1.83cm |

バランス検証は既存の姿勢ドライブを併用し、足の目標を床へ下ろして実接触を作る。
この検証時点の通常立位では足の接触が途切れたため、支持なしを支持ありとして扱わなかった。足裏統合後の通常立位は [足裏接地と速度拘束の統合](active-ragdoll.md#2026-11-03-足裏接地と速度拘束の統合) で別途測定する。
これは自立歩行や補助PDだけでの立位維持の検証ではない。
