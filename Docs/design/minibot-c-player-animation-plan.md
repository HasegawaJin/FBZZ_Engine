## 1. 到達点と動きの方向

新しい Player で「移動 → 斬る → 防ぐ → 回避 → ボスへとどめ」が成立する状態まで作る。
旧モデルのモーションは転用せず、現在の人型リグで新規制作する。既存のゲームルールを接続先として使い、双剣を前提とする武器所有・判定・クリップ選択は一刀へ移行する。

演技の方向は、軽快な小型ロボットの剣士。足裏と腰に体重を感じさせ、剣を振る瞬間に速さを集中させる。
待機と受けは両手で前に構える。歩き・走り・斬撃も両手で柄を保持する。攻撃後は両手の構えへ戻す。
待機では視線・重心・サーボの小さな調整を使い、常に大きく揺らさない。
長い剣と頭部フィンが実際のゲームカメラから読めるシルエットを優先する。

**Idle / Run_F / Slash01**を品質の基準とする。防御はガード3本で確認する。

## 3. 制作順とクリップ一覧

Action 名は `MB_C_` 接頭辞で統一する。以下は接頭辞を省略した名前。
現在は **再生用22本＋参照姿勢1本**。下表は機能別の制作枠で、参照由来の攻撃をどの枠へ使うか確定してから不足分を追加する。

| 段階 | 制作するクリップ | 本数 | 完了条件 |
|---|---|---:|---|
| 0: 接続の準備 | `Stance`（参照姿勢） | 1 | 骨格・握り・向き・縮尺・マスク・右手装着を確定し、確認用FBXがゲーム内で動く |
| 1: 品質の基準 | `Idle`, `Run_F`, `Slash01` | 3 | 接地と剣の軌道が実カメラで読め、3本の切り替えが成立する |
| 防御 | `ToBlocking`, `Blocking`, `GuardHit`, `BlockingToIdle` | 4 | 構えから防御へ入り、受け止めた反動から維持姿勢へ戻り、解除できる |
| 2: 操作の基礎 | `SwordWalk`, `JumpStart`, `FallLoop`, `Land`, `Dodge`, `RunStop` | 6 | 移動・跳躍・着地・回避と見た目のタイミングが一致する |
| 3: 戦闘一式 | `Slash02`～`Slash06`, `ChargeStart`, `ChargeHold`, `ChargeRelease`, `AirSlash`, `AirSlam`, `Execute` | 11 | 6段コンボ、溜め、空中攻撃、部位へのとどめがつながる |
| 4: 抜刀と収納 | `Draw`, `Sheathe` | 2 | 手と背中の付け替えに姿勢が合い、抜刀後に戦闘へ入れる |
| 5: 反応と決着 | `Hit_F`, `Hit_Heavy`, `Death`, `Victory`, `DefeatIdle` | 5 | 被弾・死亡・勝敗表示へ自然に接続し、モーションが途中で切れない |

必要が見えた後の追加候補: `Hit_B/L/R`、重い着地、走り出し、左右のその場旋回。
ロックオン中も正面を維持して横移動する仕様へ変更する場合は、別途ストレイフを追加する。

### 2026-09-14時点の不足と優先順

| 優先 | 未制作の動き | 判断 |
|---|---|---|
| 次 | `Hit_Heavy`（大きな被弾） | 制作済み `Hit` と区別する強いのけぞり・吹き飛びの役割 |
| 仕様次第 | `ChargeStart`, `ChargeHold`, `ChargeRelease` | 溜め攻撃を採用する場合に追加 |
| 仕様次第 | `Draw`, `Sheathe`, `Execute` | 抜刀・納刀、とどめを採用する場合に追加 |

攻撃素材は `Slash01`, `HighSpinAttack`, `JumpAttack`, `SlideAttack`, `UnderSlash`, `UnderSlashandUpperSlash` の6種がある。旧計画の `Slash02`〜`Slash06`・`AirSlash`・`AirSlam` は役割名として扱い、既存素材への割り当てとコンボのつなぎを決めてから新規制作の要否を判断する。
登攀一式・コア攻撃・通常歩き・パリィは除外済みで、不足リストへ戻さない。おともはゲーム側で制御する。

### 品質の基準となる3本の狙い

| クリップ | 初期の尺案 | 重点 |
|---|---|---|
| `Idle` | 現在4.8秒、ループ | 両手の前構えで重心移動と周囲を見る動き。足を固定し、共通の構えへ戻れる |
| `Run_F` | 接地周期と基準移動速度から決定 | 腰の上下、遊脚、接地、左腕の振りを揃える。最高速でも脚だけが高速回転しない |
| `Slash01` | 現在1.70秒（参照の1振り＋復帰） | 両手で振りかぶる → 袈裟斬り → 振り抜き。腰・胸・肩・手の順に力を伝える |

まずキーポーズを並べて輪郭と重心を確認し、次に中間姿勢と速度を調整する。
一定周期の角度変化を全身へ与えるだけの制作にはしない。肩と腰の位相差、支持脚、手首の遅れ、停止姿勢を個別に作る。

### 一刀の6段コンボ案

| 段 | 動き | つながり |
|---|---|---|
| 1 | 右上からの袈裟斬り | 短い入口。左下へ振り抜く |
| 2 | 左下からの返し斬り | 1段目の終点からそのまま返す |
| 3 | 踏み込みながら水平斬り | 刀身が胸の前を横切る軌道を明確にする |
| 4 | 踏み替えて回転斬り | 腰と足を含む全身動作へ切り替える |
| 5 | 斬り上げ | 軌道を縦へ変え、剣を上段へ運ぶ |
| 6 | 腰と踏み込みを強くした両手の斬り下ろし | 大きな打点と残心を作り、構えへ戻す |

コンボ途中には待機ポーズを挟まない。次段の開始は前段の終盤姿勢と接続する。
入力が途切れた場合だけ各段の戻りを使う。攻撃入力の先行受付・回避や防御へのキャンセルはゲーム仕様へ合わせる。
旧 `BladeSide` の左右や極性・色に意味が残っている場合、物理的な左右の剣と切り離す。装備を右手1本にしたことでゲーム上の効果まで無条件に片側へ固定しない。

## 4. Blender とゲームの責務

| Blenderで作るもの | ゲーム側で制御するもの |
|---|---|
| 腰・胸・手足の姿勢、剣を振る軌道、指の握り、表情に相当する視線・頭の芝居 | Playerの座標・向き・加減速、重力、接地、回避距離 |
| 溜め、打点、振り抜き、戻りの演技 | 攻撃受付、ヒット判定、ダメージ、無敵、キャンセル、ヒットストップ |
| 右手で持つ姿勢、両手を添える姿勢、抜刀・収納の手順 | 剣オブジェクトの手と背中への付け替え、軌跡・発光・効果音 |
| PlayerだけのAction | おともの追従・浮遊・傾き・反応 |

通常のクリップは原地で制作し、Rootのゲーム移動分を焼き込まない。骨盤の上下や体幹の回転は残す。
回避、攻撃の前進、空中叩きつけでも、ゲーム側の移動とアニメーションの移動を二重に加算しない。
全身回転では「足元の向き」と「ゲームオブジェクトの旋回」を分けて確認する。

`Run_F` は基準速度と1周期の接地点を記録し、ゲーム側の速度に合わせて再生速度を調整する。
現行の10 m/sでは再生倍率と歩幅の確認を優先する。動きが成立しない場合は高速用クリップの追加または速度調整案を提示し、見えない足滑り補正で済ませない。
回避は現行の0.36秒と減速曲線に合うよう、姿勢の進みと移動を同時に確認する。
ジャンプは踏み切り・空中・着地を分離し、着地するまでの時間を1本の固定尺へ押し込めない。

## 5. ゲームへの組み込み

### 5.1 骨格と装備

1. `Player_LOD0.fbx` と確認用クリップで、インポート後の骨名・親子・バインド姿勢・単位・正面を確認する。旧モデルのヨー補正値をそのまま流用しない。
2. 新しい54ボーンへHumanoid対応表を作り、Base / UpperBody / Armsマスクを新しい骨名で定義する。未指定ボーンが意図せず残るケースも確認する。
3. 足IK、頭の注視、足音・土煙の参照骨を更新する。例: `Foot_L/R` から `LeftFoot/RightFoot`。骨名だけでなくIKの鎖と座標も検査する。
4. 装備中は1本のSwordを `Socket_Weapon_R` に装着する。左手は姿勢上の補助とし、剣の親にはしない。
5. 背中の収納位置はChestに追従するゲーム側の装着点として定義する。剣側にも刃元・刃先の判定／トレイル用装着点を実寸に合わせて置く。新しい骨を必要としない方法を優先し、54ボーンの契約を維持する。
6. 旧二刀のオブジェクト名・ソケット・左右交互クリップ選択・トレイル・判定参照を検索して、一刀への対応を揃える。シーン内の保存値とGUID参照も対象とする。

### 5.2 再生レイヤーと割り込み

| レイヤー | 主な担当 | 注意点 |
|---|---|---|
| Base | 構え、歩き、走り、空中、着地、回避、停止 | Speed / VerticalSpeed / IsGrounded / Jump / Dodge / Stop を活用 |
| Attack（上半身Override） | 移動可能な通常攻撃 | 1～3段目の全身姿勢は制作時に持ち、走りとの合成を見て腰の寄与を決める |
| FullBody（全身Override） | 4～6段目、強い溜め攻撃、空中攻撃、Execute | 踏み替えが重要な動作を上半身だけで再生しない |
| UpperBody（上半身Override） | 抜刀・収納 | 攻撃Slotと奪い合わないよう、装備状態と再生の所有者を明確にする |
| Add_Hit | 軽い被弾の加算 | 新しい `Stance` を参照姿勢とする。通常の全身ポーズをそのまま加算しない |

強い被弾・死亡は全身で制御し、死亡時は攻撃・装備操作のSlotと入力受付を終了する。
FullBodyが有効な間は競合する上半身SlotとIK補正の重みを管理する。終了・キャンセル・被弾・シーン再読込の全経路で重みを戻す。
現行のSlotには各レイヤー1本という制約があるため、強攻撃・とどめが同時に上書きし合わないようにする。

### 5.3 時刻とゲーム判定の接続

各Actionに制作マーカーを置き、クリップごとに次を台帳へ出力する。

- fps、開始・終了フレーム、ループ、参照姿勢、想定レイヤー、Root移動方針
- 左右の接地、打点、受け姿勢到達、振り抜き終了、復帰姿勢、剣の付け替え
- 移動クリップの基準速度と接地位相

**Blenderのマーカーが現在のFBXヘルパーからゲームへ自動で届くとは扱わない。**
制作Actionのマーカーから `motion_manifest.json`（制作台帳）を出す処理を追加し、まず既存のクリップ時刻フィールド／ソケット移動時刻へ対応付ける。
ゲームのイベントトラックを使う場合はインポートと再生時の受信まで確認してから切り替える。
足音・トレイルなどをイベント化するときは、既存の距離／時間による発火との二重実行を防ぐ。

クリップ内時刻は `(markerFrame - startFrame) / fps`。ゲーム側の発生・硬直・受付時刻とは別の意味として記録する。
当たり判定の正本はゲーム側に保ち、クリップの打点を既存の時刻制御へ合わせる。
Blenderの緩急と `MotionTempo.hpp` の再生速度変化が重複して、振り出しが止まり打点直前に跳ぶことがないよう、まず素材を再生倍率1.0で確認してからゲーム側の調整を加える。
ガードの判定受付と維持・解除の条件はゲーム接続時に照合する。

主な接続先:

- `GreenWare/Assets/Animation/Player/Player.animcontroller` と各 `.mask`
- `GreenWare/Assets/Scripts/Player/PlayerControllerComponent.hpp`
- `GreenWare/Assets/Scripts/Player/BladeComponent.hpp`
- `GreenWare/Assets/Scripts/Player/PlayerParryComponent.hpp`
- `GreenWare/Assets/Scripts/Player/WeaponRigComponent.hpp`
- `GreenWare/Assets/Scripts/Utils/WeaponSockets.hpp`
- 各ステージ、Playerを含むプレファブ、勝敗演出の参照

実装時は既存アセットへ差分を当て、シーン／プレファブを生成し直さない。旧参照の撤去は新しいクリップで再生できることを確認してから行う。

## 6. 制作と検証を1本ずつ閉じる

1. 構え、準備、打点／接地、振り抜き、戻りのキーポーズを作る。
2. 正面・側面・実ゲーム相当の後方カメラで、重心、剣と床、腕と装甲、頭部フィンを確認する。
3. 中間姿勢を整え、等速再生・0.5倍速・ゲーム想定速度で確認する。静止画だけで完成判定しない。
4. 前後のActionと接続する。左右の接地位相、指の握り、武器の位置、IK/FKの切り替えを確認する。
5. 操作リグを54出力骨へベイクし、1 Action = 1 FBX = 1 takeで出力する。素材は30fps、ゲームは補間再生とする。
6. FBXを再読込して骨格・時刻・変形を比較する。Blenderの再読込時は既知のボーン自動接続補正を含める。
7. ゲーム内で通常再生、ブレンド、割り込み、ヒットストップ、速度変更、LOD切り替えを確認する。

ループは先頭と終端の姿勢だけでなく接地位相と速度の連続性も確認する。
開始フレームを1にする場合、1秒の素材は1～31であり、フレームの個数をそのまま秒数へ換算しない。
ループ終端の重複キーを再生で二重に踏まないこともインポート後に確認する。

### 合格条件

- 静止接地・ループの境目で足の瞬間移動や腰の跳ねがない。
- 基準移動速度で支持脚が滑らず、最高速・減速・旋回でも足運びが不自然にならない。
- 剣先が床・脚・頭を貫かず、片手／両手の握りが外れない。
- 打点と判定が一致し、当てた直後のヒットストップで両者が同じ姿勢に止まる。
- コンボ停止、回避キャンセル、ガードからの復帰、被弾割り込みでT/Aポーズや古いSlotが残らない。
- 納刀中に攻撃せず、抜刀・収納の付け替え時に剣が跳ばない。
- 死亡と勝敗演出の必要な姿勢がシーン遷移前に見える。現行の負け遷移は短いため、Deathの主要動作をその時間内へ収めるか演出側の変更案を別途示す。
- 同一クリップがLOD0/1/2に適用でき、LOD変更で姿勢と剣の位置がずれない。

接続コードを変更した場合のビルド・ゲーム実行確認はプロジェクト規約に従い、VSCode / Visual Studioのタスクで行う。
ビルドが必要になった段階で実行を依頼し、Blender内の検証だけでゲーム実装完了とは扱わない。
