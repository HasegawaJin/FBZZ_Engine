# Water patch selection lifetime

The cache persists pure patch selection for Finite and Horizon water. Camera and WaterCB updates, wave time, body indices, visibility decisions, draw ordering, render targets and GPU uploads remain per pass. Horizon resolves its snapped patch domain before the cache lookup.

EditorApp owns a persistent SurfacePatchSelectionCacheOwner on its recording thread and passes a shared owner into each RenderSystem call. The call pins it by value across callbacks and destroys its exclusive lease before the local pass context. Other callers omit this optional owner and keep invocation-local selection caches. This owner is independent of the existing frame geometry cache and its script-mutation guard. It keeps at most two idle view slots. Each slot retains at most eight selections and at most 16384 SurfacePatch vector-capacity units; both replacement and insertion enforce that bound. The total persistent patch-array allocation is bounded by 2 * 16384 * sizeof(SurfacePatch), plus entry/control-block metadata. Active invocation owners may temporarily keep evicted geometry alive until the invocation finishes.

A slot key contains ResourceManager instance identity and reset epoch, Scene generation, view identity and output handle id/generation. Scene and Game may use different Scene generations without evicting each other. Reset epochs invalidate old slots for that manager; changing the Scene of the same view/output invalidates that slot. Other or newly created outputs follow two-slot LRU replacement. No key or retained result owns a Scene, RenderScene, camera, GPU resource, material or resource manager.

Borrow swaps one idle slot into the invocation's context and parks any prior context cache in the busy slot. Lease destruction swaps back and restores that prior cache. A busy view or two active slots uses local invocation storage. Clear or invalidation marks active storage for discard on return. Stable slot addresses, noncopyable owners/leases and ordinary stack lifetime prevent nested callbacks from moving an outer lease's bookkeeping. The owner and context must outlive their lease. The Editor owner retains only numeric keys and immutable CPU patch arrays, with no external resource destruction dependencies. Scene or output changes miss their exact numeric key; destroying the Editor releases the idle storage.

The existing bitwise selection signature still covers surface bounds/world matrix/displacement, all LOD/morph settings, camera position/forward, projection scale, viewport height, near distance, projection kind, clipping policy and all frustum planes. It additionally records C floating-point rounding mode and SSE control bits 6..15: DAZ, exception masks, rounding and FTZ. Sticky exception-status bits are excluded. FBZZ Math's x64 SSE4.1 arithmetic uses these controls. Invalid source inputs or nonfinite frustum planes clear the cache and take the existing selector fallback; no invalid derived geometry is newly certified.

Water holds a shared owner of each immutable selection while it traverses patches. Clear, replacement, eviction and same-context nested callback activity therefore cannot destroy geometry still used by an outer traversal. Legacy Find remains available with its prior borrow-until-mutation contract; Water uses FindOwned. Completed selections are moved into const-owned storage, avoiding the former selection-array copy on a miss.

The tests exercise selector output, camera and frustum matching, eviction, capacity limits, floating-point controls, independent Scene and Game views, nested calls, and scene and resource invalidation. Water Atlas, Interface, Selection and Forward pin their immutable RenderScene inputs across resource callbacks. The Horizon test checks that a reused selection receives fresh wave time and survives eviction during Submit.
