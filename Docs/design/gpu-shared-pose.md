# GPU共有姿勢の設計（2026-10-18）

OceanEcosystem1km の個体数、アニメーション時刻、LOD頻度、材質と描画設定を維持する。120FPSのCPU予算は8.33ms。既存GPU_SHARED(2)はCPU互換出力を保持する比較用経路として残し、GPU_POSE_SHARED(3)を明示的に選択した個体だけCPU骨行列生成とCB転送を遅延する。

## データと寿命

不変のBakeデータはクリップ単位で共有する。個体は現在と前フレームそれぞれのsource/target、フレーム補間率、ブレンド率だけを保持する。CPUの時刻量子化を追加しない。同一の全パラメータを持つ姿勢だけGPU行を共有する。前フレームも毎描画フレーム再生成し、3レーンGPUプールの過去ハンドルの内容へ依存しない。リソース所有者、リセット世代、描画フレームで公開ハンドルを検証する。

## 描画契約

VS t14/t15 に現在/前姿勢のStructuredBufferを渡す。ObjectConstants.objectParams.z はGPUパレットの選択、wは現在の行列オフセット。Velocity専用のxは前姿勢のオフセット。非スキンド・粒子・MeshShaderと同時にこれらのスロットを使用しない。Common/Skinning.hlsli の行列読出しだけを拡張し、重みと行列乗算順序は維持する。Forward、DeferredのVSフォールバック、Shadow（Alpha Clipを含む）、Velocity、DecalとMask、Editorの選択輪郭に同じ契約を適用する。Probe捕捉は既存通りスキンド個体を除外する。GPUパレットを読む描画ではCPU骨CBを束縛せず、DX12のSubmit時に未使用CBをUploadArenaへ再転送することも防ぐ。未知の独自シェーダーがboneMatricesを直接読む場合はモード3の対象外とする。

## CPU遅延と復帰

boneBakeRequireCpuBones=falseを必須とし、近距離、IK/Spring/MotionWarp、外部姿勢、レイヤー、Mask、RootMotion、Morphなど既存のBake除外を維持する。GPUで表示する個体はCPUベクトルを描画の正本にしない。描画バックエンドとバッチ用プログラムが利用できることを確認した後は、画面外の個体にもCPU評価を要求しない。GPU資源・LOD互換性・Dispatchに失敗した場合は保存された現在/前姿勢をCPU評価し、CBおよびcompute入力を同一フレーム内に復元する。モード変更やCPU読出し要求への復帰時も前姿勢を復元する。初回の切替時はCPUで一度評価して履歴を確立する。CPUからGPUへの切替直後だけは既存CPU前姿勢の転送が一度残り、その後のGPU再生中は現在・前姿勢ともCPUのFKとCB更新を省く。CPUのboneMatrices/nodeGlobalTransformsは遅延中の描画の正本ではない。骨GameObjectとTransform即時同期の契約は変更しない。

## 検証と導入

まず現在/前GPUパレットを全描画consumerへ接続し、CPU互換を残したモード2でStandaloneの画像・実測を確認する。次にモード3のCPU遅延を有効にし、同条件で比較する。小さい人工骨格の単体テストで時刻保持、前姿勢、GPU失敗のCPU復帰を検証する。対象シーンの実個体数と画像を比較し、改善が確認できた段階のみSDKとシーンへ反映する。120FPSに到達しない場合は実測値と残るCPU処理を報告する。

## 世代と互換性

RHIの同期処理後にはScene世代、AnimatorのEntityとComponent lifetime、ResourceManager所有者・リセット世代・フレーム、Asset世代と姿勢パラメータを再検証する。入力がその間に退役した場合は古いCPU seedで描かず、新しい姿勢の準備を待つ。対応外のCPU骨読出し、FiberやMeshTrailなどのCPU姿勢consumer、Common/Skinningを使用しない独自シェーダーではboneBakeRequireCpuBonesをtrueに保つ。標準以外のconsumerへモード3を自動適用しない。

Assetモデルの成功・拒否キャッシュは同じインポート世代内だけ有効とし、世代更新で破棄する。リグ制御が存在しないときの骨走査を省く判断は各Actorで最新のComponent所属を読む。

## Render executorとキャッシュの破棄

現在・前姿勢をクリップ組ごとの不変ジョブへまとめ、描画スレッドへの同期呼出し1回で連続して再生する。Scene/Animatorの公開は呼出し元へ戻ってから世代検証後に行う。GPU再生キャッシュはロック下で空の状態へ切り離し、ロックを解放した後にRHIへ資源を返す。資源破棄が同期的に描画スレッドを待つ間に再生用ロックを保持しない。GPU資産はジョブが強参照し、描画スレッドの処理中にScene側のキャッシュが無効化されても寿命を維持する。

通常のモード3では既存の距離LODを保つ。CPUフォールバックの個体だけ更新頻度を強制的に増やさず、切替・履歴無効化・状態遷移では直ちに再評価する。
