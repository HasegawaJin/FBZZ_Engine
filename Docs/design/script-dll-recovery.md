# Scripts DLL の失敗と復帰

2026-09-15。GreenWare のコンパイルエラーで全スクリプトが未読み込みになった事例への対策。

- コンパイル失敗時は実行中の DLL とシーンを維持する。拒否したビルド出力を Editor が削除しない。
- DLL の更新日時は警告に使い、互換性は ABI 署名で検証する。リンク順序だけで互換 DLL を拒否しない。
- DLL の初期化・ABI 照会・登録の失敗を検知し、登録途中のファクトリを解放してから DLL を解放する。
- Reload はシーンと直前の DLL コピーを保存する。新 DLL のロード・登録・シーン復元に失敗したら、直前のコピーを再ロードし、保存状態からスクリプトを再生成する。
- 新旧 DLL の静的 DataAsset 登録が干渉するため、同時にロードしない。これはランタイム状態の完全なトランザクションではなく、シリアライズ可能な状態への復帰である。
- 復帰にも失敗したら理由をログに残す。未登録スクリプトの保存データは維持し、次の正常ビルドで再生成する。
- 初回 DLL ロードと開始済みビルドの完了処理は、自動ホットリロード設定から独立させる。
- DLL が未読み込みの Play 要求は再ビルドを予約して終了する。成功後に再度 Play を押す。ソース修正時の既存監視でも再試行でき、失敗だけを理由に自動ループはしない。
- Rebuild / Reload Scripts は既存の `script.reload` 操作を通す。要求フラグの消費処理が欠けていたため、TickScriptCompile でビルド予約へ変換する。ホットリロード無効時も明示要求は処理する。Play 中は操作を無効にする。
- 明示 Rebuild は生成対象の一覧を同期し、MSBuild の `/t:Rebuild` で Scripts を作り直す。`BuildProjectReferences=false` により起動中の Engine DLL は再リンクしない。自動ソース監視は増分ビルドを維持する。

## 検証

VSCode / Visual Studio から Editor と Scripts をビルドする。
正常ロード後のコンパイルエラーで旧スクリプトが動くこと、修正後に新 DLL へ切り替わることを確認する。
ABI 不一致・登録エクスポート欠落・シーン復元失敗では旧 DLL の再ロードと復元ログを確認する。
DLL が無い状態、ホットリロード無効状態でも初回ロード／ビルドを完了できることを確認する。
Build Output の Rebuild、コマンドパレットの Reload Scripts の両方で、ビルド開始ログと完了通知が出ることを確認する。
StageSelect の入力、BGM、保存フィールドと DataAsset 解決を再確認する。
