# Render Pass Viewer

## 目的

Debug > Render Pass Viewer から専用のドッキング可能なパネルを開き、Scene / Game の実行順、CPU / GPU 時間、各パス直後の出力を確認する。

## 所有と操作

- `RenderPassViewerPanel` を通常の `IPanel` として登録する。開閉は既存の `panel.set_visible` の投影で、View / Debug / コマンドパレット / AI が同じ状態を扱う。
- 開閉状態は個人設定へ保存する。旧 Project Settings の Pass Viewer チェックは専用パネルへの案内に置き換える。
- キャプチャはパネルが所有する `RenderPassCapture` に保持する。表示中の選択ビューだけへ渡し、他ビューやアセットプレビューから上書きさせない。対象ビューが背面でも描画する。

## パス出力

- パス一覧と入出力は RenderGraph の宣言を正本とする。実行順とカリング結果を表示する。同名パスは出現順で区別する。
- SSR / MotionBlur / VolumetricLight の Compute 出力と LensFlare の輝度抽出画像も登録簿と出力宣言へ載せる。TAA は処理後の LDR 登録先を、書き終えた履歴 RT へ更新する。
- グラフのパス完了フックを CPU / GPU 計測の終了後に呼ぶ。選択したパスの直後だけ、登録簿から解決したカラー添付・深度・2D テクスチャを専用 RT へ可視化する。
- 入力も選択可能だが、画像はそのパス終了時点の内容。同じ HDR を書く Sky / Water / Particle 等も個別の時点で見られる。
- 選択した画像 1 枚だけを保持する。パスのカリングや実行順を変えず、後続の上書きやリソース再利用から画像を独立させる。
- `IRenderer::RenderDebugPreview` が描画先・ビューポート・シザーを保存復元する。API 固有の処理は DX11 / DX12 内に閉じる。次の Submit は通常どおり自身の描画状態を束縛する。
- 未指定定数バッファを維持する DX11 では、診断で差し替えた b5 の VS / PS 束縛も復元する。
- カラー、R/G/B/A、符号付きベクトル、深度の線形化、露出、値域調整を提供する。G-Buffer の法線は既に 0–1 に符号化されているため RGB で表示する。
- パス・リソースが消えたフレームやシェーダー準備失敗時に古い画像を表示しない。閉じたパネルと終了時は専用 GPU リソースを解放する。

## 計測と制限

GPU 時間は遅延収集値で、ビューを厳密に識別できない既存 GPU profiler の結果は「遅延・複数ビュー共有」と明記する。未計測を 0 ms にしない。キャプチャの追加描画は選択パス自体の時間から外すが、フレーム全体には診断コストが乗る。

Compute のバッファや 3D / Cube テクスチャはこの 2D プレビューの対象外。画像がないパスでも入出力とタイミングは表示する。パス内部の早期 return は実行済みパスのままで、描画命令が発行されたことまでは保証しない。

## 検証

- パス完了フックが計測終了後、次の書き込み前に呼ばれ、カリングされたパスでは呼ばれないことを GoogleTest で確認する。
- キャプチャ選択の同名パス識別・構成変更・無効化を CPU テストで確認する。
- VS Code の Debug Editor ビルドと Tests タスク、両バックエンドの全シェーダーコピーのコンパイルを実施する。
- 実機では Scene / Game 切替、Shadow 深度、G-Buffer 各添付、Bloom、Sky / Particle 直後、リサイズ、Play 開始停止、パネル閉じ直しを確認する。
