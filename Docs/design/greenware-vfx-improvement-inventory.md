- `GreenWare/Assets/VFX/Game/` に9本、`VFX/Serpent/` に5本の専用 `.vfx`。`Templates/VFXLine/` の6本はテンプレートとして別扱い。
- `VfxManagerComponent.hpp` に14本の既定パスと各再生入口がある。Stage_01 / Stage_02 に同マネージャーの記述を確認。
- `.vfx` は通常の GameObject 階層を持つプレハブ形式。設計は [vfx-prefab.md](vfx-prefab.md) に従う。
- 刀の軌跡・溜め発光・回避残像・ボスの衝撃波・ビーム・死亡には、スクリプトで組み立てる層もある。`.vfx` の本数だけでは全体を数えられない。
- `VFX/Textures/` に26枚（静止素材24枚、8×8の煙・爆発2枚）。別途 `Textures/Particles/` に既存素材集がある。
- `T_Slash_Arc.png`、`T_Dust_Puff_2x2.png`、`T_Burst_Rays.png` は画像を直接確認。それ以外はファイル・設定・呼び出し元の調査。
- 実機の動画・通常カメラでの再生は未確認。以下の改善方向は制作仮説であり、白飛び・遮蔽・タイミングの不具合を実機で断定したものではない。
- 古いコメントには撤去済みの極性ゲームや登攀が残る。今回の対象は現行2ボスとプレイヤー。休眠機能の演出は復活させない。

## 見た目の共通方針

1. 通常斬撃は「細く鋭い」、弾きは「硬い接触」、切断は「裂けて分離する」、巨体の着地は「重く広がる」と形を分ける。
2. 強さの段階は通常ヒット → 連撃締め・溜め → 通常弾き → Just弾き → 部位切断・撃破。明るさだけでなく幅・方向・時間差で差を付ける。
3. 接触直後の芯、追いかける火花・破片、消えていく煙・跡の順で読ませる。すべての層を同時に最大にしない。
4. 刃・ボス本体・次の攻撃予兆を常に読めるようにする。煙は床と進行方向の後方へ、閃光は接点へ集める。
5. 刀身の赤青、弾きの白〜氷色、プレイヤーの成功・回避の緑、危険表示の既存色を起点にする。色の意味を変更する場合はHUD・予兆と一緒に決める。
6. 予兆は色に加えて円・帯・輪郭・進行で区別する。装飾の輪が攻撃範囲に見えないようにする。

## テクスチャ制作候補

画像生成は質感のばらつきを作る用途へ絞る。既存素材は直接上書きせず、候補を並べて比較してから差分を適用する。

| 素材 | 必要性と方式 | 最初の仕様案 | 用途 |
|---|---|---|---|
| 土煙の静止バリエーション | 最優先の画像生成候補。現行は滑らかな丸い塊が見える | 無彩色RGBA、独立4種を各512²。中央に密度、薄く崩れた縁、端に透明余白 | 走行、踏みつけ、転倒、蛇全般 |
| 床を這う粉塵 | 画像生成候補 | 無彩色RGBA、横長1024×512。低い厚み、不規則な吹き流れ | 巨体の接地、突進、衝撃波の後流 |
| 薄い排煙 | 既存煙との比較後に画像生成 | 無彩色RGBA、512²、方向性のある細い煙、余白あり | 切断面、ビーム接触 |
| 焦げ・擦過跡・ひび | 既存Decal素材との比較後に画像生成 | 各1024²。上面正投影、照明・背景・影を焼き込まない、外縁をフェード | ビーム、蛇の擦過、巨体の接地 |
| 斬撃の尾・侵食マスク | shader/手続き生成を優先 | 1024×256、流れ方向とUV端を定義、芯を潰さない | 刀の軌跡と溜め斬り |
| 閃光・光条・輪・火花 | 既存を再利用し必要なら手続き生成 | 単純な輝度マスク。輪郭・幅・減衰を数値制御 | ヒットと弾きの差別化 |
| 歪み・ノイズ | 手続き生成 | シームレス、RGの中立値と用途を明記 | 熱、刃の尾、ビーム |
| 煙・爆発の動画アトラス | 既存flipbookを先に評価。必要なら連続シミュレーションからベイク | 同じ時間列・同じカメラ・同じ露出。セル間余白とmipを検証 | 大きい煙・撃破 |

ユーザー指定は「ChatGPT image 2.5」。生成段階で利用可能なモデル指定方法を確認する。
現時点でそのモデルを使用したとは扱わない。今回の洗い出しでは画像生成を実行していない。
画像生成で作る静止画4種はバリエーションであり、時間連続するflipbookにはしない。
6方向照明・法線・フローマップを画像の見た目だけから正しいデータとして扱わない。
色・透明度・チャンネルは各mat/shaderの読み方に合わせ、黒背景を透明と取り違えない。

## 最初の制作セット

1. 通常斬撃の軌跡と通常ヒットを基準にする。連打しても接点と相手の姿勢が見える強さを決める。
2. 通常弾き・Just弾きの2種を揃え、短い動画で一目で違いが分かる形にする。
3. 連撃締め・溜め開始／成立／解放を同じ刀の表現で伸ばす。
4. 部位切断を最大の報酬にする。実部位の分離が閃光に隠れないことを確認。
5. 土煙素材を比較し、転倒・踏みつけ・蛇へ共通展開する。
6. ビーム、予兆、回避、被弾、撃破を整え、両ステージ通しで統一する。

初回の改修対象は既存 `.vfx` 4本（SlashHit / Parry / ParryJust / Execute）、shader 2系統（WeaponTrail / SlashCut）、それらの材質。
新規 `.vfx` はCharge / ChargeReadyを候補とし、FinisherHit / ChargedHitは既存分岐で不足するときに追加する。
生成テクスチャの初回候補は土煙4種と床粉塵1種。既存素材集との比較で採否を決める。

## 制作・検証条件

- `.vfx` は既存階層へ差分を適用する。`VfxBinding` は子の名前に依存するため、名前変更はスクリプトとセットで行う。
- 新規アセットは `.meta` とGUID参照を整備する。既存のパス参照を新規制作の手本にしない。
- shader変更前にエンジン側・ゲーム側・includeの全コピーを検索し、存在する全コピーを修正・コンパイルする。今回の検索ではParticleは両側、WeaponTrail / SlashCut / BossBeam / PlayerGhost等はGreenWare側で見つかった。
- マテリアルのブレンド、深度書き込み、描画順、soft particles、色空間、mipでの縁を確認する。
- 音・止め・画面効果は既存の呼び出し側と同期させる。vfxへ追加して二重発火させない。ImpactFeedbackManagerだけで全戦闘イベントを網羅しているわけではない。
- 単体確認は開始直後・最大・減衰の3点。合格判断は通常のゲームカメラと再生速度で行う。
- Stage_01は5連撃→溜め→通常/Just弾き→転倒→切断→ビーム→撃破。Stage_02は浮上→叩きつけ→走り抜け→檻→節切断→終盤→撃破を確認する。
- 連続ヒット、ビームと土煙、転倒と切断が重なる場面で、予兆とプレイヤーが読めることを確認する。
- 画面全体の白飛び、巨大な平面スプライト、床との硬い交差、同じ粉塵模様の反復、切れた残像、flipbookのセル混入を点検する。
- GPU負荷は変更前後を同条件で測る。粒数だけでなく画面占有率、透明層の重なり、点光源、生成数を確認する。予算値は実測後に決める。
- ビルド・shaderコンパイルはプロジェクト規約どおりVS Code / Visual Studioのタスクで実施。洗い出し段階ではビルド不要。
