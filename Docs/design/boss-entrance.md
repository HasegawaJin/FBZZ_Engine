# ボス登場演出と Stage02 開幕配置

## 方針
- Boss01: 鉄骸の番人 — IRON WARDEN。脚を含む全身を低い位置から見せる。
- Boss02: 双獄の大蛇 — NIDHOGG。2体を共通のタイトルとして見せ、HP表示では左右を識別する。
- Boss03: 焔翼の熾天使 — SERAPH。翼の展開を見せる。
- 既存 BossCameraDirector を拡張。タイトル、異名、アクセント線をシーンの HUD Canvas に著作し、フェード同期。最後の0.65秒で登場前の追従構図へ戻してから操作を返す。
- 登場はシーン開始ごとに1回。Boss03の再展開や蛇2体目では再生し直さない。ポーズ中は進めない。

## Stage02
Player は (0,0,-11)、正面 +Z。南側の穴O8から5m、内周I5/I6から約5.7m離す。
左蛇 I3→O4、右蛇 I2→O2 から出現。両経路の弦長は約8.1mで既存の8〜10.5m制約を満たす。根のTransformではなく実際の初期経路を指定する。
最初の1秒で構え、両蛇を北側の左右に同時に見せる。カメラ焦点(0,1.5,9)、距離18m。初期経路の設定が無効なら既存の探索へ戻す。

## 検証
シーンTOML、ID重複、経路距離、SDK APIの存在を静的確認。VSでScriptsをビルドし、各ステージの入室・再挑戦・ポーズ復帰・登場後の初手を実機確認する。

## 撃破と生体感のある発光
Boss03にも共通EnemyDeathVfxを付け、1.7秒の連鎖爆発後に2.4秒で装甲と翼をディゾルブさせる。素材の元の色と粗さを保つ専用材質を用意する。Glowは共有アセットを書き換えず各メッシュのMaterialInstanceで操作する。通常は浅い呼吸、警告・崩しは強い脈、撃破時は共通ディゾルブへ制御を渡す。

### 発光の読み分け
通常の呼吸は浅く、攻撃する部位のみ強く発光する。Boss03は分割された翼メッシュ単位で予告を出し、使わない翼は平常色を保つ。ダウン中は琥珀のゆっくりした脈で反撃可能を伝える。Boss01の本体被弾とBoss02の節被弾は短い暖白色の反応とし、死亡ディゾルブの材質へは上書きしない。

## Stage03遷移時の地形貫通対策
出現点の地形高さは約2.0m、Playerは3.2mで保存されている。再現実機がないため遷移固有の原因は未確定。Stage03のPlayerに地形復帰を有効化し、物理後に足元が地形より下へ抜けた場合のみ地表へ戻す。通常のジャンプと水平速度は保つ。シーン切替時は固定ステップの未消化時間をリセットし、前シーンの時間を新シーンへ持ち込まない。

全3ステージの回避入力バッファを0.15→0.20秒、ジャンプを0.12→0.16秒へ調整。行動中に押した次の操作を拾いやすくし、無敵時間や移動速度は維持する。

## 装甲の状態別マテリアル演出
発光以外のSkinnedMesh材質にもMaterialInstanceで色・粗さを重ねる。元のalbedo・roughnessを保存し、Boss01は予兆、Boss02はブレイク蓄積、Boss03は予兆の進行に従って暖色と艶を増す。ダウンでは寒色と粗い表面へ滑らかに移行し、終了後は元の値へ戻る。Boss01・03の被弾は短い明色の反応を重ねる。発光材質・死亡ディゾルブ材質は対象外。共有材質のパスが変わったスロットには書き込まない。

SDKのMaterialInstance APIと差分の静的確認を実施。ビルドと明暗・ブルーム込みの実機評価は未実施。

### シーン遷移直後の座標確定
StageSelect → Load → Stage03では、読み込んだSceneのlocal座標だけが復元され、world座標は最初のPrePhysicsまで未計算だった。Play中のTransformEditorPreviewは無効なので、先行するScriptのOnAwake/OnStart/OnUpdateは原点を読む。PlayerBossBlockComponentはPlayerとBossのBodyが重なったと判定するとworldからlocalへ押し出し位置を書き、その結果、保存されたPlayerの(約0,3.2,-30)が原点付近に上書きされ得る。
SceneManagerのFactory成功後、初回スクリプトより前にFlushWorldTransformsを一度実行する。親子階層を含めて位置・回転・スケールを確定し、Play中の遷移もEditorプレビューと同じ座標で開始する。出現座標の固定や地形高さによる補正追加では対処しない。
SceneManagerTestsでStageSelect → Load → Stage03を固定ステップ無しのフレームで遷移させ、OnAwake/OnStartの座標と誤った押し出しが無いことを検証する回帰テストを追加。VSからEngineとテストのビルド・実行、実機での遷移確認が必要。
