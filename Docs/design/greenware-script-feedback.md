# GreenWare の制作からスクリプト API へ戻す改善

2026-09-29。既存の ScriptModules、必須 Component 検証、AudioSource / AudioSystem を拡張する。

## 初期化

- Script フェーズの入口で EntityID と ScriptEntry の inspectionId を写し取る。各コールバック前後に実体を引き直し、配列再確保・削除・差し替えを跨いで参照を保持しない。
- モード切替の後処理、全対象の Awake、全対象の Start、全対象の Update の順で実行する。同じ GameObject の複数 Script も同じ規則。
- 開始時に非アクティブな対象、コールバック中に追加された対象は次フレームから初期化する。無限に生成する Awake でも当該フレームを終えられる。
- Pause、編集時実行の opt-in、無効 Script の Awake / Start という既存契約は維持する。途中で非アクティブ化・破棄された対象は残りの処理を実行しない。
- Awake で自己の初期状態を用意し、Start で他者の Awake 済み状態を参照する。Start 相互依存や、動的生成されたマネージャーの出現待ちは順序保証の対象外。

## 必須設定

- 必須 Component に加え、同一 GameObject の必須 Script、型付き参照、DataAsset の未設定・解決失敗を共通の診断へ集約する。
- Inspector はアセットをロードせず、未設定・ファイル存在・キャッシュ済み型を検査する。Play 前と全 Awake 後の Start 前は実際にアセットを解決し、パース失敗や型不一致まで検査する。
- アセットの必須性は反射メタデータとして宣言する。保存キー・TOML 形式は変更しない。観測値の getter は評価しない。
- 必須 Script / Asset / Ref の不備では Start と以降の更新を止める。既存の Component 宣言は診断のみの互換契約を維持する。自動生成・自動割当はしない。
- 不足対象のオブジェクト名、Script 型、設定キー、理由を表示する。復旧は設定を直して再生をやり直す。
- Awake 後に Start が止まった Script にも、Scene の破棄時は OnDestroy を届ける。手動で enabled を戻しても、実行コールバックから検証停止を回避できない。

## 独立したループ音

- 自 GameObject の主音声とは別のループを ScriptAudioProxy から所有・制御する。既存 AudioSystem の距離減衰・バス・停止処理を共用する。
- ゲーム側はハンドル、クリップ、音量、ピッチ、出力設定を扱う。AudioSource の再生要求フラグと音声用オブジェクトの生成は Engine に閉じる。
- 名前だけでシーン全体を検索しない。同名キーを持つ複数個体の再生を分離し、古いハンドルで別個体や再利用後のオブジェクトを操作できないようにする。
- 所有者破棄・Script の再生成・モード変更・無効化でハンドルを失効させる。音源がトークンを所有し、Script と AudioManager は弱参照する。Script は破棄時にトークンだけを失効させ、破棄中の Scene へアクセスしない。音源自体が消えた場合も AudioManager の次回更新で停止・回収する。
- UpdateLoop は要求の受付を返す。クリップの読み込み・デバイス再生の成功や聴感は保証しない。同一クリップ・バスへの更新は音を先頭へ戻さず、無音への更新は停止する。設定はメインスレッドから操作する。
- ComponentArray の末尾削除で所有物が残っていたため、削除時に空いた実体も初期化する。音声の寿命失効時には既に開始された停止フェードを再開始しない。

## 検証と公開

初期化の全体順序、途中の生成・削除、設定不足の診断と実行停止、音声の複数所有者・停止・古いハンドルを自動テストで確認する。ポートフォリオの抜粋は実ファイルから生成し、変更前のリビジョン・変更後の内容・検証範囲を併記する。実機での聴感と自動テストの結果は区別する。
