# 海・草・毛の外観拡張と描画性能の実測

海とGrass/Furは、プロジェクト側の材質・HLSLで外観を編集できるようにした。通常MeshRendererでは、同一フレームのビュー間で共有する幾何キャッシュの材質コピーを削減した。草の既定品質では高速化を示す結果は得られておらず、軽量品質は任意設定として提供する。

## 外観の作り方

- [Water材質の編集](water-appearance-authoring.md)：既存の `.mat` とシェーダー反映を使い、Toon／Realistic例を複製・編集する。形状、CPU水面問い合わせ、媒質などのサービスはWaterComponent側に残す。任意の頂点変位がCPU問い合わせへ自動反映される契約ではない。
- [波・水面の設定](water-waves.md)：波形・水面サービスの設定と制約。
- [Grass/Furのプロジェクト外観](fiber-project-appearance.md)：Blade／Shell／Fin／Hybridのシェーダーファミリー、型付きパラメーター、既存テクスチャslotを使う。共通の変形・coverage・各描画パスを維持する。
- [Fiber描画と品質設定](fiber-rendering.md)：配置、品質、LOD、描画経路の詳細。独自外観の追加シェーダーコストは、以下の既定材質ベンチマークでは保証しない。

上表の初期実装では25万本の時間増加が残ったため、同じ現行ネイティブ上でシェーダーだけを隔離した。品質対応前Aと初期実装Bを旧→新→新→旧で比較し、各ケースのwarmupを3000フレームへ延長した。25万本の大きな増加は再現せず、旧0.877568msに対し初期実装0.878592／0.879616msだった。ただし10万本等では小さな増加が繰り返されたため、既定6分割を先に返し、不要なclamp・整数変換を低分割側へ移したCを採用した。

## 結果の適用範囲

Cullingは変更前後1回ずつ、草は旧基準1回と現行既定2回の固定順序測定。CPU/GPU clock、温度、allocator/cache状態、電源条件、他process負荷を独立に統制していない。p95は各採取区間の分布で、実行間の信頼区間ではない。

CullingのBegin〜EndはVSync無効のPresentを含むが、snapshot観測コピーとログ出力は含まない。草のCPU提出／GPUパスにはroot生成、初回upload、Engine抽出、地面、postprocess、読戻しを含まない。草のframeWallはBegin/Endとprofiler回収を含む。両harnessの時間を相互に加算・比較しない。GPU区間を総GPU時間やFPSへ変換せず、非同期GPU標本をCPUの同一フレーム値とみなさない。

計測原本は作業記録 `EngineIteration3` の `CullingComparison.*`、`GrassDefault6*-Comparison.*`、`GrassSelected3Shadow1-Comparison.*` と元ログ／PNG。恒久保存用の小さなJSONには、主要数値、品質区分、PNG hash、未解決テスト、原本hashを記録した。

### 修正内容と利用方法

- DataAsset保存テスト：テスト環境の AssetManager 初期化とプロジェクト相対パスが実際の起動条件に合っていなかった。正しい初期化と同一アセット参照を検証し、保存・Undo の判定を維持した。
- Package開始条件：Package の開始判定が共有状態 ctx.managedBuildBusy を見ていなかった。要求 ID の生成・処理開始・設定変更より前に拒否するよう修正し、元の判定と回帰を維持した。
- `StripeFur` はShellと専用Finの完全なファミリーを持ち、Hybridを通常描画とプレビューで使用できる。各パスで共有形状・被覆を維持し、不完全なファミリーは診断して互換の標準材質へ戻す。
- 独自Furは直接頂点スキニングで、姿勢・深度・影・選択・速度の読戻しを検証した。DeferredはGBufferだけでなく最終HDR出力で独自外観の反映を検証した。imported clip再生と独自Compute pre-skinは今回のカスタム外観検証では未検証であり、未対応と断定しない。
- Waterは共有形状契約の未宣言・頂点契約違い・表面契約違いを診断し、標準の共有形状と従来外観へ戻す。元の独自shader参照と編集値は保存する。契約metadataは作者の保証で、任意HLSLの意味検証や頂点変形からCPU物理を自動生成する機能はない。対応する波形変更はWaterWavesAssetと共有サンプリングを使う。
- 独自外観のobject-like macroを使ったincludeも更新検知するよう修正した。Finのincludeだけを編集した後の再読込と色変更を実GPUで確認した。任意のHLSLプリプロセッサ全体を実装するものではなく、未対応include式は古い結果の無断再利用を避けて保守的に再コンパイルする。
- 材質は既存`.mat`の型付きパラメーターと既存8テクスチャslotを使用する。Fiberの`tex5`は共有形状マスク用である。材質・ファミリーを複製し、Inspectorで値を編集・保存し、ソース変更後はshaderを再読込する。Realistic／Toonは編集可能な作例であり、閉じた組み込みスタイル選択ではない。

DX12 validationがcleanだったことは、この合格結果から推定しない。任意のユーザーshader、完成した美術品質、独自変形と境界・CPU物理の自動一致まで保証するものではない。
