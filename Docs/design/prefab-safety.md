# Prefab の更新と差し替え

Prefab の出所は `prefabAssetPath` に GUID 参照として保持する。既存のプロジェクト相対パスも読み、共通のアセット解決口で現在の実体へ解決する。表示用のパスヒントは比較キーから除外する。

各ルートの `prefabSourceSnapshot` は、そのインスタンスに最後に適用したアセット定義を保持する。差分はこの旧定義とインスタンスを比較して求め、新定義へ適用する。内部参照はインスタンス GUID をアセット内のソース ID に正規化して比較する。IK、Bone、SkinnedMeshRenderer の内部参照に付随する名前ヒントもソース名へ戻し、名前の一意化を個別変更と誤認しない。Apply の前に他インスタンスの差分を採り、Apply の元になった実体と更新に成功した実体だけの基準定義を進める。これによりディスク更新、Prefab 編集モード、シーン再読込でも未変更の値へ新定義が届く。

基準定義を持たない旧シーンでは、現在のアセットとの差を個別変更として保護する。過去の基準値を推測して個別調整を上書きしない。次の正常な更新から基準定義を保持する。基準定義が壊れている場合は更新を拒否する。

プロパティ内のアセット参照も比較時だけ GUID へ正規化し、改名で変わるパスヒントを除く。サブメッシュ番号やスプライト ID は比較に残す。差分パッチと Inspector の表示には元の値を使う。

子の追加、削除、親変更は基準定義のソース ID 集合と親ソース ID から検出する。構造の三方マージは未対応なので、個別調整を保持する自動更新では当該インスタンスを変更せず警告する。ルートを別のシーンオブジェクトへ配置することやインスタンス名の自動接尾辞は構造変更に含めない。明示的な Revert は構造の個別変更を破棄してアセット定義へ戻す。

通常の保存と生成は複数ルートを扱う。接続は保存と同じ全選択範囲の ID 重複解消を使う。既存インスタンス一つからの Apply、Revert と自動更新は単一ルートのアセットに限定し、複数ルートなら元の階層を保持して拒否する。旧形式の名前による親参照は一意のソース ID へ変換してから全階層の循環を検証する。ID の無い旧形式は配列順からソースキーを作るため、並べ替えを含む更新の完全な対応は保証しない。

差し替えはファイルの読込、階層検証、容量確認、全コンポーネントの一時 Scene への復元を先に終える。その後で新階層を追記し、追記に失敗した場合は新しい実体だけを除去して旧階層の識別子を戻す。旧階層は最後に破棄するため、失敗時に未保存値や既存 EntityID を失わない。新旧階層を同時に保持できない場合は変更せずに失敗する。

成功時は旧 EntityID から新 EntityID への対応表で、保存対象の Component と Script の非所有参照を移す。削除された実体を指す参照は無効化する。一時 Scene から補完コピーする参照は別の対応表で移し、既存の無関係な実体を巻き込まない。任意の C++ ローカル変数に保持した raw pointer は更新対象に含まれない。

保存時はコンポーネント内の内部参照もソース ID へ戻す。Prefab は自分自身への出所リンクと基準定義を含まない。

検証は CPU のみで Instantiate、Apply、ディスク更新、シーン再読込、改名、失敗時の保持、外部参照移行を行う。GPU がある実行環境では既存のリソース復元口を使う。
