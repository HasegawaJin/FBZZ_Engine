# 静的MeshRendererの変更通知とフレーム間geometry再利用

静的Meshのworld・逆転置・world境界を再利用する。C# MeshサービスとRuntimeMeshSystemの通知で同一フレームの共有snapshotを失効させ、行列は実際に入力が変わった個体だけ再計算する。通知されない公開フィールド変更もgeometry build時にbit単位で照合する。全候補の照合はO(R)で残る。材質・選択・GPU変形・previous worldは現在の抽出境界から更新する。

## 条件

- Windows、Core i7-14700F、RTX 4070。ハードウェア・driver・全実行物のSHA-256は[環境記録](Final-cpu-Environment.json)。
- MSVC、既存のReleaseビルドツリー、LTO有効。変更前に保存したDLLと最終DLLを別フォルダーへ置き、同じ計測exeを両方で使用した。読み込んだEngine DLLの絶対パスも検証した。
- High priority、HighQoSを各子プロセスで設定・読戻し検証。A/B/B/A/A/Bの順で各3プロセス。CPU主表はaffinity=16（1論理CPU固定）の追加確認、実描画はaffinity=240（4論理CPU）。先に完了したCPUのaffinity=240の結果も参考表と生標本へ全件残した。両CPU測定のソース・exe・DLLは同じ。
- CPU抽出は1,000体で2,000 warmup、10,000体で120 warmupの後に400標本/プロセス。実描画は1,000体で600 warmup、他は120 warmupの後に600標本/プロセス。初期のsmoke実行と採用前の版は本表に混在させない。
- 表のP50は各プロセスのP50の中央値。P95/P99は同条件3プロセスの全標本をまとめた値。「前 / 後」を示す。ms、短いほどよい。単一機の実時間計測であり統計的な普遍性は主張しない。

## 実Mesh描画フレーム

既存のRegularMeshRenderPerformanceTestで1920×1080のRTへ実際にcubeを描いた。DX12 native renderer、Forward / Unlit、CPU geometry、instancing・shadow・VSyncは無効。開始からEndFrameまでを計測し、Presentを含む。CPU Profilerは停止した。変更はフレーム内で適用し、可視件数を一定にするためZ方向だけ動かす。読戻し・画像hash・ログ出力は時間計測外。Editorのproducer/worker処理やゲームの更新を含むStandalone全体FPSの測定ではない。

| 条件 | 前P50 | 後P50 | 変化 | P95 前 / 後 | P99 前 / 後 |
|---|---:|---:|---:|---:|---:|
| 1,000体・全件可視 | 1.0277 | 0.9939 | -3.3% | 1.1155 / 1.0981 | 1.1965 / 1.2235 |
| 10,000体・100体可視・無変更 | 8.2548 | 7.4373 | -9.9% | 9.0103 / 8.1728 | 9.6276 / 8.8654 |
| 10,000体・1%変更 | 7.6047 | 8.2253 | +8.2% | 8.9096 / 10.4839 | 9.6746 / 12.3840 |
| 10,000体・全件変更 | 7.6957 | 7.7961 | +1.3% | 9.1745 / 8.5525 | 10.1577 / 9.1664 |
| 10,000体・反対向き2ビュー | 17.4237 | 17.2713 | -0.9% | 18.7647 / 18.7167 | 20.4817 / 19.6976 |

1万体の単一ビューは100体を可視とする。2ビュー目は320×180で、1ビュー目と反対側の9,900体を描く。全試行で1ビュー目の画像hashと描画・cull・三角形件数が前後一致し、2ビュー目も非背景画素と描画件数を検証した。GPU passの時間は既存のsource/view/resource付き完了標本から取得し、[実描画集計](Final-gpu-Summary.json)へ含めた。GPU全体時間としては扱わない。

## 結果の読み方

1論理CPU固定の無変更抽出は1,000体で-24.8%、10,000体で-8.1%。一方、初回2抽出は1,000体で+10.0%、10,000体で+15.3%となり、再利用領域を作る初期費用が残った。

実描画の静的1万体は-9.9%だったが、1%変更は+8.2%と後退した。全件変更は+1.3%。無変更の入力の数学計算を省けることはテストで確認したが、走査・入力照合・出力配列作成の費用は残る。全条件の高速化やエンジン全体FPSの改善を示す結果ではない。

## 正しさ・ビルド

- 最終Release LTOのCPU回帰93件、GPUスキニング58件が合格。追加・既存の抽出53件は固定seedで並べ替えても合格。
- 無変更時の再構築ゼロ、変更した入力だけの再計算、C#サービスからの通知、raw pose/mesh書き込み、回転・負スケール、親子変更、active/LOD/shadow、previous world、Component/Entity/Scene寿命、4 Sceneを超えた退役、公開snapshotの独立性を確認した。
- pose witnessを意図的に外すと境界・逆転置のテストが失敗し、元のbyte列へ復元後に50件が合格した。[不正変更の検証](MutationTests.json)、[復元証拠](Mutation.json)。
- 連続移動時のcache失効を意図的に外すと、停止後に古いworld・境界が出るテストが失敗した。元のソースとLTO入力mapをbyte単位で復元し、52件が合格した。[停止後の負例](MovingMutationTests.json)、[復元証拠](MovingMutationProof.json)。
- Sceneのdense fallback再試行を止めると停止後の復帰テストが失敗した。共有geometry版の更新を止めるとC#の変更が旧snapshotへ閉じ込められるテストが失敗した。両方ともソース・入力mapをbyte単位で復元し、53件が合格した。[復帰の負例](DensityMutationTests.json)、[通知の負例](NotificationMutationTests.json)。
- 通常DLLの公開シンボルを検証してからLTO export mapを更新し、既存ordinalを維持した。最終版は全native入力hash・module export名/ordinalと、前後の計測exe同一性を再検証した。[実行物監査](FinalArtifactAudit.json)。
- 保存した変更前のnative入力mapと最終mapの差はEngineの4ファイルだけで、残る1,354入力は一致した。変更前のDLLは保存原本とbyte単位で一致し、公開した256個の生標本archiveも解凍後hashを再検証した。[公開証拠の監査](PublishedEvidenceAudit.json)。
- Engine、CPU/GPUテスト、計測exe、EditorLauncher、SandboxStandaloneのビルドが合格。既存のMSB8028 / LTO-PCH系警告を記録し、新しいコンパイルエラーはない。

## 範囲と費用

- 私有領域はスレッドごとに最大4 Scene。非所有Mesh identity、Entity/Component寿命、入力witness、行列と境界を保持する。容量は過去最大件数まで保持し、Scene slotの退役で解放する。通知用の個体索引はない。
- 初回Sceneは従来経路を使い、次のgeometry buildで再利用値を作る。連続移動は従来経路へ戻す。64体以上で75%以上の既存値が2回続けて変わるSceneは16 buildだけdense経路へ戻し、必ず再検証する。静止後は再利用へ復帰する。
- 毎フレームのRenderScene出力配列の確保、材質・bindingの再解決、draw command構築、GPUへのobject uploadは既存経路。今回それらの削減率は主張しない。
- 確保回数・永続領域の実測byte・GPU upload量は未計測。プロセス終了後のworking-set取得は利用できなかったため値を掲載しない。
- 同一フレームで通知なしのScene変更を行う場合、従来どおりRenderFrameGeometryCacheを使わない。cross-frameの現在値検証はgeometry buildで必ず行う。

初版ではcold buildと全件変更に後退が出たため、初回・高変動時のfallbackを追加し、最後に不要な通知用索引と同一値での行列失効を削除した。[初版CPU計測](Iteration1-cpu-Summary.json)と[初版実描画](Iteration1-gpu-Summary.json)は分離して保存した。プロセス実行品質とwarmup条件を揃え直したため、初版と最終版の値を直接割って改善率を算出していない。

設計・参考実装は[静的Mesh再利用の契約](../../design/static-mesh-render-reuse.md)。今回のソース差分は[task差分](TaskDelta.patch)。生標本は[manifest](RawManifest.json)に列挙したgzip内へ保存し、解凍後SHA-256を付けた。元のDLL・全文ログはScratch/StaticMeshReuse20261023に保持している。HighQoS設定は[Microsoftの公式契約](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation)に従う。

その後の1%変更の追試と、同一フレームの材質需要の重複判定を削減した結果は[追加の性能比較](../2026-10-23-partial-mesh-motion/Report.md)に分離した。本報告の数値と生標本は当時の版の記録として保持する。
